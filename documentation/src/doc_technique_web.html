1. Présentation du site

Le site web Savora est un site vitrine doublé d'un module de réservation en ligne. Il a deux rôles :

RôleDescription
VitrinePrésenter le restaurant : concept, philosophie, horaires, localisation
RéservationPermettre au client de réserver une table en vérifiant les disponibilités en temps réel

1.1 Technologies utilisées

OutilRôle

Svelte 5Affichage réactif (runes : $state, $effect)

1.2 Schéma de l'architecture

SvelteKit est un framework full-stack : il sert les pages au navigateur et exécute aussi du code serveur. Le navigateur n'accède jamais directement à la base ; ce sont les routes serveur (+server.ts) qui interrogent PostgreSQL via Drizzle.

2. Mise en route

2.1 Lancer le site

① Installer les dépendances 
cd SavoraWeb
npm install
② Configurer la connexion à la base (fichier .env) 
DATABASE_URL="postgresql://utilisateur:motdepasse@localhost:5432/savora"
③ Démarrer le site 
npm run dev                        → http://localhost:5173

2.2 Visualiser la base — Drizzle Studio

Drizzle fournit une interface web pour voir et modifier la base. On la lance dans un terminal dédié :

npm run db:studio                  → https://local.drizzle.studio

On y voit les trois tables (reservations, clients, daily_quotas) et leur contenu.

À montrer au jury : faire une réservation sur le site, puis rafraîchir Drizzle Studio → la ligne apparaît. C'est la preuve que Drizzle enregistre bien en base.

5. Le module de réservation

C'est le cœur du site. Le client choisit, dans cet ordre :

  • le nombre de couverts (1 à 6) ;
  • la date (calendrier) ;
  • l'horaire (midi ou soir) ;
  • puis remplit ses coordonnées et valide.

5.1 Disponibilités en temps réel

Quand le client change de date, le site demande les places restantes à la route /api/availability/{date}. Les créneaux complets sont grisés et ne peuvent pas être sélectionnés. Cet affichage se met à jour automatiquement grâce à la réactivité de Svelte 5.

5.2 Enregistrement de la réservation

À la validation, le site envoie la demande à /api/reservations. Cette route serveur vérifie les règles (couverts 1–6, date non passée, conditions acceptées, quota non dépassé), puis enregistre la réservation via Drizzle.

Important : aucun e-mail n'est envoyé. La réservation est enregistrée avec le statut « en attente » et un récapitulatif s'affiche à l'écran. C'est le personnel qui la validera ensuite (dans l'application de gestion).

6. Accès aux données avec Drizzle

Drizzle permet d'écrire des requêtes SQL en TypeScript, de façon typée (le code vérifie les noms de colonnes) et sécurisée (protection automatique contre les injections SQL).

6.1 Calcul des places restantes (lecture)

// queries.ts — additionne les couverts déjà réservés pour un service
export async function reservedCovers(date, period) {
  const [row] = await db
    .select({ total: sql`coalesce(sum(${reservations.partySize}), 0)` })
    .from(reservations)
    .where(and(
      eq(reservations.date, date),
      eq(reservations.mealPeriod, period),
      inArray(reservations.status, ['pending', 'confirmed'])
    ));
  return Number(row?.total ?? 0);
}

6.2 Enregistrement d'une réservation (écriture)

// +server.ts — insère la réservation, puis crée le client si besoin
const [created] = await db.insert(reservations)
  .values({ partySize, date, timeSlot, mealPeriod, ... , status: 'pending' })
  .returning();

if (!(await clientExists(email)))
  await db.insert(clients).values({ civility, firstName, lastName, phone, email });

Ainsi, une réservation crée automatiquement la fiche client si elle n'existe pas encore (le lien se fait par l'adresse e-mail).

8. Déploiement

Le site est déployé sur un serveur Debian (machine virtuelle), avec PostgreSQL installé nativement sur le serveur.

① Base de données — créer la base et un utilisateur dédié (non-root) 
sudo -u postgres psql
CREATE USER savora_user WITH PASSWORD 'motdepasse';
CREATE DATABASE savora OWNER savora_user;
② Construire et lancer le site 
npm install
npm run build
node build                         → site sur le port 3000
③ Apache (reverse proxy) — le serveur web public redirige vers le site 
ProxyPass        /  http://localhost:3000/
ProxyPassReverse /  http://localhost:3000/

Le site est alors accessible depuis l'adresse IP du serveur.
